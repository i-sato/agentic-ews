# Fase 2: Daftar batch (tautan), fetch, masking dengan mapping, validasi, hitung
Tugas:
1. Jalankan migrasi 002 (sudah dari repo). Halaman Batch: form "Tambah batch" menempel tautan Google Sheets (boleh banyak, satu per baris). Server mengurai `sheet_id` dan `gid`, membaca nama sheet dari metadata, mem-parse nama dengan `parseNamaBerkas` (hasil dapat diedit: ID pelatihan, tema/alias, level + sumber, tanggal; TA otomatis dari tanggal mulai). Tolak tautan/batch duplikat (ID pelatihan+TA, sheet_id+gid).
2. Pembacaan sheet di `server/sheets/`: Google Sheets API read-only dengan service account (env `GOOGLE_SERVICE_ACCOUNT_JSON`, server saja; terima JSON mentah maupun base64, deteksi dari karakter pertama `{`; cakupan `spreadsheets.readonly`). Tampilkan petunjuk "bagikan sheet sebagai Viewer ke <email service account>". Jika akses ditolak -> `akses_ditolak` + petunjuk. Baca hanya tab bernama dari konfigurasi ("All Pendaftar Web"); tab hilang -> `tab_hilang` (item validasi). Cadangan: unggah .xlsx/.csv dengan alur yang sama.
3. Satu fungsi `prosesSheet(batchId, rows, pemicu)`: (a) hitung ulang dari kolom modul (abaikan % LMS dan STATUS; bandingkan, beri peringatan `lms_tidak_cocok`); (b) `kunciBaris` + `petakanAlias` dengan membaca `private.alias_map` yang ada (alias dipakai ulang; baru dibuat; hilang ditandai, tidak dihapus; duplikat -> item validasi). SIMPAN HANYA alias, kunci, dan nomor registrasi di `private.alias_map` (kolom nama/instansi sudah dihapus oleh migrasi 003; jangan menambahkannya kembali). Nama dan instansi dipakai di memori saja untuk hashing/pemrosesan, tidak disimpan, tidak di log. Baris tanpa nomor registrasi -> item validasi `no_registrasi_kosong`; (c) upsert `peserta_masked`; (d) ringkasan, `histogram`, `checksum` -> upsert `snapshot` (satu per batch per hari WIB; checksum sama -> berubah=false); (e) `bandingkanSnapshot` (perbandingan alias kemarin vs hari ini diambil sebelum upsert) -> anomali ke Antrean Validasi; (f) perbarui `last_fetch_*` dan tulis `fetch_log`. Pembatalan: `batal`, dikeluarkan dari hitung. Catatan lintas batch HANYA bila pengaturan `catatan_lintas_batch_aktif` = true; kunci memakai `kunciOrang` mode sesuai `noreg_stabil_lintas_batch` ('ya' -> noreg, 'tidak' -> nama, 'belum_diverifikasi' -> fitur mati). Sediakan kontrol admin untuk memverifikasi pengaturan ini.
4. Sentinel keluar: semua teks yang akan dikirim ke Gemini dan semua keluaran laporan diperiksa dengan `containsIdentifier(teks, daftarNoRegBatchIni)`; terdeteksi -> blok, catat di audit_log tanpa mengutip nilainya.
4b. Baris mentah hanya di memori; jangan di log, jangan di respons API. Respons hanya agregat.
5. Antrean Validasi: daftar, aksi diterima/diubah/ditolak, audit_log.
6. Batch level belum terkonfirmasi: diproses sementara, label "belum masuk capaian resmi".
Uji: `tests/golden` dan `reference` hijau; uji fetch dua kali dengan data berbeda: alias sama, `baru` benar, anomali muncul saat progres sengaja dimundurkan.
